# 3D

The spatial dimension is fixed when Mallard is built: `-DMallard_DIM=3` gives a 3D solver for meshes of tetrahedra, hexahedra, prisms and pyramids, in any mix. 2D and 3D builds can live side by side:

```bash
cmake -S . -B build3d -DCMAKE_BUILD_TYPE=Release -DUSE_SYSTEM_KOKKOS=OFF \
      -DKokkos_ENABLE_THREADS=ON -DMallard_DIM=3
cmake --build build3d -j
```

## Inputs

3D inputs use the same keys as 2D ([input reference](input.md)), with three differences:

- vectors have three components: `u = [u_x, u_y, u_z]`, `gravity`, `rhou`;
- expressions are in `x`, `y` and `z` (and `t` where allowed);
- generated meshes are boxes, with two more boundary zones, `back` (z = 0) and `front` (z = Lz).

| `[mesh] type` | Cells per block of the `Nx × Ny × Nz` box |
|---|---|
| `cartesian` | one hexahedron |
| `cartesian_tet` | six tetrahedra |
| `cartesian_prism` | two triangular prisms |
| `cartesian_pyramid` | six pyramids |
| `cartesian_mixed` | hexahedra, pyramids and prisms in successive thirds of x |

Gmsh meshes (format 2.2 or 4.1) work as in 2D: each physical surface becomes a boundary zone.

## Example: Sod shock tube in 3D

The Sod shock tube on a 200 × 4 × 4 box of hexahedra with slip walls on all six sides:

```toml
[run]
t_stop = 0.2
cfl = 0.5

[mesh]
type = "cartesian"
Nx = 200
Ny = 4
Nz = 4
Lx = 1.0
Ly = 0.02
Lz = 0.02

[initialize]
type = "analytical"
rho = "x < 0.5 ? 1.0 : 0.125"
u = ["0.0", "0.0", "0.0"]
p = "x < 0.5 ? 1.0 : 0.1"

[[boundaries]]
name = "left"
type = "symmetry"
[[boundaries]]
name = "right"
type = "symmetry"
[[boundaries]]
name = "bottom"
type = "symmetry"
[[boundaries]]
name = "top"
type = "symmetry"
[[boundaries]]
name = "back"
type = "symmetry"
[[boundaries]]
name = "front"
type = "symmetry"

[numerics]
riemann_solver = "HLLC"
time_integrator = "SSPRK3"

[numerics.face_reconstruction]
type = "MUSCL"
limiter = "venkatakrishnan"

[physics]
type = "euler"
gamma = 1.4
p_ref = 1.0
T_ref = 1.0
rho_ref = 1.0

[output]
check_interval = 100000

[[write_data]]
prefix = "./solut/sod"
format = "vtu"
time_interval = 0.2
variables = ["RHO", "U", "P"]
```

```bash
build3d/src/Mallard -i input.toml --kokkos-num-threads=4
```

The output is VTU with 3D cells and the velocity as a 3-vector `U`, for ParaView or `tools/mallard_vtu.py` (`read_vtu_cells`). On hexahedra the solution is one-dimensional to round-off (transverse velocities below 10<sup>−13</sup>) and its L<sub>1</sub> density error against the exact solution, 2.97 × 10<sup>−3</sup>, equals that of the 2D run on 200 × 4 quadrilaterals to three digits.
