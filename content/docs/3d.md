# 3D

!!! note "Not in Mallard 0.2.0"
    3D is on Mallard's `main` branch and will be part of the next release; build from `main` to use it. The commands and results below were checked on `main` (commit db1c3d2).

The spatial dimension is fixed when Mallard is built: `-DMallard_DIM=3` gives a 3D solver for meshes of tetrahedra, hexahedra, prisms and pyramids, in any mix. 2D and 3D builds can live side by side; build the 3D one in its own directory:

```bash
cmake -S . -B build3d -DCMAKE_BUILD_TYPE=Release -DUSE_SYSTEM_KOKKOS=OFF \
      -DKokkos_ENABLE_THREADS=ON -DMallard_DIM=3
cmake --build build3d -j
```

## Inputs

3D inputs use the same keys as 2D ([input reference](input.md)), with three differences:

- vectors have three components: `u = [u_x, u_y, u_z]`, `gravity`, `rhou`;
- expressions are in `x`, `y` and `z` (and `t` where allowed);
- generated meshes are boxes, with two more boundary zones, `back` (z = 0) and `front` (z = Lz).

| `[mesh] type` | Cells per block of the `Nx × Ny × Nz` box |
|---|---|
| `cartesian` | one hexahedron |
| `cartesian_tet` | six tetrahedra |
| `cartesian_prism` | two triangular prisms |
| `cartesian_pyramid` | six pyramids |
| `cartesian_mixed` | hexahedra, pyramids and prisms in successive thirds of x |

Gmsh meshes (format 2.2 or 4.1) work as in 2D: each physical surface becomes a boundary zone.

## Example: a 3D Sod shock tube

The Sod shock tube on a 200 × 4 × 4 box of hexahedra with slip walls on all six sides, with MUSCL reconstruction:

```toml
[run]
t_stop = 0.2
cfl = 0.5

[mesh]
type = "cartesian"
Nx = 200
Ny = 4
Nz = 4
Lx = 1.0
Ly = 0.02
Lz = 0.02

[initialize]
type = "analytical"
rho = "x < 0.5 ? 1.0 : 0.125"
u = ["0.0", "0.0", "0.0"]
p = "x < 0.5 ? 1.0 : 0.1"

[[boundaries]]
name = "left"
type = "symmetry"
[[boundaries]]
name = "right"
type = "symmetry"
[[boundaries]]
name = "bottom"
type = "symmetry"
[[boundaries]]
name = "top"
type = "symmetry"
[[boundaries]]
name = "back"
type = "symmetry"
[[boundaries]]
name = "front"
type = "symmetry"

[numerics]
riemann_solver = "HLLC"
time_integrator = "SSPRK3"

[numerics.face_reconstruction]
type = "MUSCL"
limiter = "venkatakrishnan"

[physics]
type = "euler"
gamma = 1.4
p_ref = 1.0
T_ref = 1.0
rho_ref = 1.0

[output]
check_interval = 100000

[[write_data]]
prefix = "./solut/sod"
format = "vtu"
time_interval = 0.2
variables = ["RHO", "U", "P"]
```

```bash
build3d/src/Mallard -i input.toml --kokkos-num-threads=4
```

The output is VTU with 3D cells and the velocity as a 3-vector `U`, for ParaView or `tools/mallard_vtu.py` (`read_vtu_cells`). On hexahedra the solution is one-dimensional to round-off (transverse velocities below 10<sup>−13</sup>) and its L<sub>1</sub> density error against the exact solution, 2.974 × 10<sup>−3</sup>, is that of the same scheme in 2D on 200 × 4 quadrilaterals ([validation](../validation.md#sod-shock-tube)) to all four digits.

## Example: spherical explosion

The [`explosion_3d`](https://github.com/MatthewBonanni/mallard/tree/main/examples/explosion_3d) example is the spherical explosion of Toro (*Riemann Solvers and Numerical Methods for Fluid Dynamics*, 3rd ed., §17.1.3): a sphere of radius 0.4 at ρ = 1, p = 1 in a gas at ρ = 0.125, p = 0.1, run to t = 0.25. One octant, [0, 1]³, is computed on 64³ hexahedra with symmetry planes at x, y, z = 0 and transmissive outer faces; fifth-order TENO-E, HLLC, SSPRK3. It takes about 10 minutes on 6 CPU threads:

```bash
cd examples/explosion_3d
../../build3d/src/Mallard -i input.toml --kokkos-num-threads=6
```

The cells collapse onto one curve, so the computed flow stays spherically symmetric on the Cartesian mesh, and that curve follows the one-dimensional reference: the mean absolute difference in density is 0.004 (cells with r < 0.95), most of it at the discontinuities, which the 64³ mesh spreads over two to three cells. Set `type = "cartesian_tet"` in the input to run the same case on tetrahedra.


## Validation: Taylor–Green vortex at Re = 1600 {#taylor-green-vortex}

The Taylor–Green vortex is the standard test of a scheme's resolution of transition and decaying turbulence (case C3.5 of the International Workshop on High-Order CFD Methods; Brachet et al. 1983): in a periodic box [−π, π]³, the velocity u = sin x cos y cos z, v = −cos x sin y cos z, w = 0 rolls up, breaks down into small vortices and decays, at Re = V<sub>0</sub>L/ν = 1600, Mach 0.1 and Pr = 0.71. Because the flow keeps the mirror symmetries of its initial state, Mallard's `taylor_green_3d` example computes only the octant [0, π]³ with symmetry planes on all six faces: 64³ hexahedra there are equivalent to the workshop's 128³ grid of the full box. Fifth-order TENO-E, HLLC, SSPRK3 at CFL 0.8, to t = 20 (32,220 time steps, on one NVIDIA A100). The reference is the workshop's 512³ pseudo-spectral DNS.

The kinetic energy decays like the DNS: the dissipation rate peaks 1.3% higher and 0.85 time units earlier, and follows the DNS through the turbulent decay to t = 20. The enstrophy shows what that resolution costs: at its peak the resolved velocity gradients account for 38% of the dissipation, and the scheme's numerical dissipation for the rest, as is usual for this case on a 128³ grid. A run on 128³ hexahedra in the octant (256³ equivalent) is in progress.
